# `errors`

Every entry point in `@exortek/security` that can fail throws a `SecurityError` carrying a stable, machine-readable
`code`. **Branch on `code`, never on the message** — messages may change between versions, codes never do.

<Tabs items={['ESM', 'CommonJS']}>
  <Tabs.Tab>
    ```js
    import { SecurityError, ErrorCode } from '@exortek/security'
    ```
  </Tabs.Tab>
  <Tabs.Tab>
    ```js
    const { SecurityError, ErrorCode } = require('@exortek/security')
    ```
  </Tabs.Tab>
</Tabs>

## `SecurityError`

```ts
class SecurityError extends Error {
  name: 'SecurityError';
  code: string; // one of ErrorCode
  status: number; // suggested HTTP status
  cause?: unknown; // wrapped underlying error, when applicable
}
```

Extends the built-in `Error`. Adds a stable `code` (see [ErrorCode](#errorcode)) and a **suggested HTTP status** —
adapters use this to translate the error into a response.

```js
import { SecurityError, ErrorCode, csrf } from '@exortek/security';

try {
  csrf.generate('too-short');
} catch (err) {
  if (err instanceof SecurityError && err.code === ErrorCode.INVALID_ARGUMENT) {
    console.error('config bug:', err.message);
    process.exit(1);
  } else {
    throw err;
  }
}
```

<Callout type="info">
  **Not every failure throws.** `csrf.verify` returns `false` on malformed or mismatched tokens — that's a normal
  authentication outcome, not an error. `cors()`'s decision object carries an `allowed: false` flag for denials, same
  reasoning. Errors are reserved for **programmer** or **configuration** mistakes.
</Callout>

## `ErrorCode`

Codes are **stable across minor versions** — new codes may be added; existing codes are never renamed or repurposed.
`@exortek/security` throws exactly 4 codes; every CSRF / CORS / rate-limit / redirect auth outcome is a returned
decision (`false`, an `{ allowed: false }` object, a deny), never a throw — see the Callout above.

| Code               | Meaning                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| `INVALID_ARGUMENT`  | Type / range / shape validation failed on a function argument or config option.                |
| `PATH_TRAVERSAL`    | `safeJoin` refused a segment that would escape the base directory, or a NUL byte in a segment. |
| `BODY_TOO_LARGE`    | `safeJsonParse` input exceeded `maxBytes` (only in `mode: 'throw'`).                            |
| `REQUEST_TIMEOUT`   | `timeout()` hit its deadline, or its `signal` aborted.                                          |

<Callout type="warning">
  All four codes carry HTTP status **400** — `SecurityError.statuses` is an empty map, so every instance falls
  through to `defaultStatus: 400` unless a caller passes `{ status: ... }` at the throw site, which nothing in this
  package currently does. Don't assume `REQUEST_TIMEOUT` is a 504 or `BODY_TOO_LARGE` is a 413 — check `err.status`
  if you need to be sure, or map `err.code` yourself (see below).
</Callout>

## Which code comes from where?

| Module                              | Codes it emits                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `csrf.generate`                      | `INVALID_ARGUMENT` (short / missing secret)                                                           |
| `csrf.verify` / `verifyForSession`   | never throws for auth outcomes — return `false`                                                       |
| `headers`                            | `INVALID_ARGUMENT` (bad HSTS preload eligibility, invalid CSP source, ALLOW-FROM frameguard)          |
| `cors`                               | `INVALID_ARGUMENT` (`credentials: true` + reflect-any, bad maxAge, non-2xx `optionsSuccessStatus`)    |
| `safeRedirect`                       | `INVALID_ARGUMENT` (bad `defaultTo`, non-string `allowedHosts` entries) — the _input_ never throws    |
| `rateLimit.*`                        | `INVALID_ARGUMENT` (bad options), no throws from `check()` itself                                     |
| `safeJoin`                           | `PATH_TRAVERSAL`                                                                                       |
| `safeJsonParse` (`mode: 'throw'`)    | `BODY_TOO_LARGE`                                                                                       |
| `timeout()`                          | `REQUEST_TIMEOUT`                                                                                       |
| Middleware adapters                  | Wrap the above; adapter-level config errors are `INVALID_ARGUMENT` (bad options, missing cookie plugin for CSRF) |

## Mapping to your own HTTP statuses

Every `SecurityError` reports status `400` regardless of `code` (see the Callout above). If you want
CSRF-style-403 / timeout-style-504 semantics in your own error handler, map `err.code` yourself:

```js
function toHttpStatus(err) {
  if (!(err instanceof SecurityError)) return 500;
  switch (err.code) {
    case ErrorCode.BODY_TOO_LARGE:
      return 413; // reinterpreted — the package itself reports 400
    case ErrorCode.REQUEST_TIMEOUT:
      return 504; // reinterpreted — the package itself reports 400
    case ErrorCode.PATH_TRAVERSAL:
    case ErrorCode.INVALID_ARGUMENT:
    default:
      return 400;
  }
}
```

## Handling patterns

**Config errors — die at boot:**

```js
try {
  await app.register(securityPlugin, options);
} catch (err) {
  if (err instanceof SecurityError && err.code === ErrorCode.INVALID_ARGUMENT) {
    console.error('security misconfigured:', err.message);
    process.exit(1);
  }
  throw err;
}
```

**Verification outcomes — branch, don't throw:**

```js
// CSRF, checkOrigin, safeRedirect, cors — all return booleans / decisions
if (!csrf.verify(cookie, header, secret)) return res.status(403).end();
if (!checkOrigin(req, { allowedOrigins })) return res.status(403).end();
const { safe, url } = safeRedirect(next, { allowedHosts });
res.redirect(url); // safe or not, url is always safe
```

**Adapter errors — propagate to your framework's handler:**

```js
// Nothing to do — Fastify and Express both catch async throws and
// route them to their error handlers.
app.setErrorHandler((err, req, reply) => {
  if (err instanceof SecurityError) {
    return reply.code(toHttpStatus(err)).send({ error: err.code });
  }
  return reply.code(500).send({ error: 'InternalError' });
});
```
