# RP-Initiated Logout

OpenID Connect **RP-Initiated Logout 1.0** — the relying party sends the end
user to the OP's `end_session_endpoint` with an `id_token_hint`; the OP ends
its session and, after validating the `post_logout_redirect_uri`, redirects
back.

## Relying party — `client.endSessionUrl`

```js
const logoutUrl = await client.endSessionUrl({
  idTokenHint: idToken,                         // required
  postLogoutRedirectUri: 'https://myapp.com/',
  state: 'xyz',
});
// redirect the user to logoutUrl
```

The `end_session_endpoint` is taken from `endSessionEndpoint` in the client
config when set, otherwise resolved from the OP metadata (cached).

## OpenID Provider — `endSessionHandler`

```js
const provider = createProvider({
  // ...
  logout: {
    postLogoutRedirectUris: ['https://myapp.com/'],   // exact-match allow-list (or { [clientId]: [...] })
    onLogout: async ({ sub }) => sessionStore.destroyForUser(sub),
    // idTokenHintMaxAge: '30d',                     // how long past exp a hint is still accepted
  },
});
```

<Callout type="warning">
  `post_logout_redirect_uri` is **exact-matched** against the registered list
  before any redirect — an unregistered URI gets a `400`, never a redirect
  (the open-redirect lever). Configuring `logout` auto-advertises
  `end_session_endpoint` in discovery.
</Callout>

The handler:

- calls `onLogout({ sub, clientId, idTokenHint })` (best-effort — never
  blocks the redirect) to clear the OP session,
- redirects to a **registered** `post_logout_redirect_uri`, echoing `state`,
- returns a `{ logged_out: true }` confirmation when no redirect is
  requested.

`sub` comes only from an `id_token_hint` that **verifies** against the OP's
published JWKS (or its signing key) with the configured alg and issuer — an
unsigned or foreign hint names no subject, so nobody can force another user's
logout. Logout hints are frequently expired, so `exp` is tolerated for
`idTokenHintMaxAge` (default `'30d'`). A `client_id` parameter must match the
hint's audience, and with `postLogoutRedirectUris` as a `{ [clientId]: uris }`
map the redirect is checked against the verified hint's client.
