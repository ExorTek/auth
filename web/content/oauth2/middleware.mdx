# Login middleware

`mountOAuthLogin` (Express) and `oauthLoginPlugin` (Fastify) wire the
login + callback routes for a `createOAuth` hub — one call, no
hand-written `authorize` / `callback` glue. Every platform is served from
the one backend through two interaction modes.

## `web` mode — browser redirect

The flow session lives in an HMAC-signed (or JWE-sealed) httpOnly cookie,
or in the `createOAuth` store. Best for a server-rendered app.

```js
import { mountOAuthLogin } from '@exortek/oauth2/express';

mountOAuthLogin(app, {
  oauth,
  mode: 'web',
  cookie: { secret: process.env.SESSION_SECRET }, // signs the flow session
  callbackPath: '/auth/:provider/callback',       // must match createOAuth's `callback` template
  onSuccess: ({ req, res, user }) => res.redirect('/'),
  onError: ({ res, error }) => res.status(400).send(error.code),
});
```

<Callout type="info">
  `seal: 'jwe'` encrypts the cookie instead of only signing it, so the
  client sees ciphertext — not the `state` / `code_verifier` / `nonce`.
  Requires `@exortek/jwe`.
</Callout>

## `api` mode — client-held session

No cookie: the start route returns the opaque `session` in JSON and the
client (mobile / SPA / CLI, RFC 8252 / AppAuth) hands it back on the
callback. Best for a native app or a token API.

```js
import { oauthLoginPlugin } from '@exortek/oauth2/fastify';

await app.register(oauthLoginPlugin, {
  oauth,
  mode: 'api',
  secret: process.env.SESSION_SECRET, // protects the client-held session
});
// GET  /auth/:provider          → { authorizeUrl, session }
// POST /auth/:provider/callback → { user, tokens }   (body carries { session, ...query })
```

## Options

| Option         | Default                       | Purpose                                             |
| -------------- | ----------------------------- | --------------------------------------------------- |
| `oauth`        | —                             | the `createOAuth` hub                               |
| `mode`         | `'web'`                       | `'web'` (cookie / store) or `'api'` (client-held)   |
| `loginPath`    | `/auth/:provider`             | start route (router `:provider` syntax)             |
| `callbackPath` | `/auth/:provider/callback`    | must match the `callback` template of `createOAuth` |
| `secret`       | —                             | protects the client-held session (`api` mode)       |
| `cookie`       | —                             | `{ secret, name, path, secure, sameSite, maxAge }`  |
| `seal`         | `'sign'`                      | `'sign'` (HMAC) or `'jwe'` (also encrypts)          |
| `onSuccess`    | redirect / JSON               | `({ req, res, user, tokens }) => …`                 |
| `onError`      | 400                           | `({ req, res, error }) => …`                        |

The routes are mounted exactly at `loginPath` / `callbackPath` — taken
verbatim, no global hook, so nothing runs on the rest of your app.
