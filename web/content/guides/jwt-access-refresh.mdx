# JWT access + refresh tokens

Short-lived **access** tokens for API calls, long-lived **refresh** tokens to
get new ones — with the reuse detection (RFC 6749 §10.4) most teams reinvent by
hand. [`@exortek/jwt`](/jwt)'s `tokenPair` ships it natively: a stolen refresh
token trips the detector and revokes the whole family.

<Steps>

### Log in — issue a pair

```js
import { tokenPair } from '@exortek/jwt/token-pair';
import { createStore } from '@exortek/jwt/stores';

const store = createStore('memory', { gc: { strategy: 'interval' } }); // or redis
const secret = { access: process.env.JWT_ACCESS_SECRET, refresh: process.env.JWT_REFRESH_SECRET };

app.post('/login', async (req, res) => {
  const user = await authenticate(req.body); // your check (see the password guide)
  if (!user) return res.status(401).json({ error: 'invalid credentials' });

  const pair = await tokenPair.create(
    { sub: user.id, roles: user.roles },
    {
      secret,
      access: { alg: 'ES256', expiresIn: '15m' },
      refresh: { expiresIn: '7d', store },
    },
  );
  // { accessToken, refreshToken, accessExpiresAt, refreshExpiresAt, familyId }
  res.json(pair);
});
```

### Call APIs — verify the access token

```js
import { verify } from '@exortek/jwt';

async function requireAuth(req, res, next) {
  const token = (req.get('authorization') ?? '').replace(/^Bearer\s+/i, '');
  try {
    const { payload } = await verify(token, secret.access, { alg: ['ES256'] });
    req.user = payload; // { sub, roles, ... }
    next();
  } catch {
    res.status(401).json({ error: 'invalid or expired token' });
  }
}

app.get('/api/me', requireAuth, (req, res) => res.json(req.user));
```

### Refresh — rotate and detect reuse

```js
app.post('/refresh', async (req, res) => {
  try {
    const next = await tokenPair.rotate(req.body.refreshToken, {
      secret,
      access: { alg: 'ES256', expiresIn: '15m' },
      refresh: { expiresIn: '7d', store },
      detectReuse: true, // default
      reuseWindow: 5, // seconds of grace for network races
    });
    res.json(next); // a fresh access + refresh pair
  } catch (err) {
    if (err.code === 'REFRESH_REUSED' || err.code === 'REVOKED') {
      // The family is compromised (or already gone) — force a full re-login.
      return res.status(401).json({ error: 'session revoked, please sign in again' });
    }
    throw err;
  }
});
```

</Steps>

<Callout type="warning">
  On `REFRESH_REUSED`, **never** silently issue a new pair — the entire token
  family is revoked and the user must re-authenticate. That is the whole point:
  a leaked refresh token becomes useless the moment the legitimate client rotates.
</Callout>

## Why rotation + reuse detection

Each refresh is single-use: rotating it marks the old one consumed and issues a
new pair. If a *consumed* refresh is presented again outside the grace window,
one of two clients is holding a stolen token — so `tokenPair` revokes the whole
family (`familyId`) rather than trusting either side. Access tokens stay short
(`15m`) so revocation propagates fast without a database hit on every request.

- **Access token** — short-lived, stateless, checked with `verify` and a
  mandatory `alg` allowlist.
- **Refresh token** — opaque by default (random bytes, only a hash in the
  store), rotated on every use, revocable per family.

the front door.
