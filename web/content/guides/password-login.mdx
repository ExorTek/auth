# Email + password login

The classic flow, done right: [`@exortek/password`](/password) for Argon2id
hashing and constant-time verification, [`@exortek/session`](/session) for
sealed, rotation-aware cookies. No password ever hits your logs, and old hashes
migrate themselves on the next login.

<Steps>

### Sign up — hash the password

```js
import { argon2, strength } from '@exortek/password';

app.post('/signup', async (req, res) => {
  const { email, password } = req.body;

  // Optional: reject weak passwords up front.
  if (strength(password).score < 3) {
    return res.status(400).json({ error: 'password too weak' });
  }

  const phc = await argon2.hash(password); // Argon2id PHC string, OWASP defaults
  await db.users.create({ email, passwordHash: phc });

  res.status(201).json({ ok: true });
});
```

### Log in — verify, rehash, issue a session

```js
import { verify, needsRehash, argon2 } from '@exortek/password';
import { createSessionManager } from '@exortek/session';

const sessions = createSessionManager({
  secret: process.env.SESSION_SECRET,
  ttl: '7d',
  idleTtl: '30m',
});

app.post('/login', async (req, res) => {
  const { email, password } = req.body;
  const user = await db.users.findByEmail(email);

  // `verify` auto-detects the algorithm from the stored PHC prefix and runs in
  // constant time. Always run it (even on unknown users) to avoid leaking which
  // emails exist via response timing.
  const ok = user ? await verify(password, user.passwordHash) : await verify(password, DUMMY_HASH);
  if (!user || !ok) return res.status(401).json({ error: 'invalid credentials' });

  // Silent migration: an older bcrypt/scrypt hash is upgraded to current params.
  if (needsRehash(user.passwordHash)) {
    await db.users.update(user.id, { passwordHash: await argon2.hash(password) });
  }

  const { cookie } = await sessions.issue({ userId: user.id, claims: { roles: user.roles } });
  res.setHeader('Set-Cookie', cookie);
  res.json({ ok: true });
});
```

### Protect routes — verify the session cookie

```js
async function requireUser(req, res, next) {
  const session = await sessions.verify(req);
  if (!session) return res.status(401).json({ error: 'unauthenticated' });
  req.user = session;
  next();
}

app.get('/me', requireUser, (req, res) => res.json(req.user));
```

### Log out — revoke the session

```js
app.post('/logout', async (req, res) => {
  const { cookie } = await sessions.revoke(req);
  res.setHeader('Set-Cookie', cookie); // expires the cookie + kills it server-side
  res.json({ ok: true });
});
```

</Steps>

<Callout type="info">
  Keep a constant `DUMMY_HASH` (one real Argon2id hash of a random string) so the
  "user not found" branch does the same work as a real verify — otherwise
  response timing reveals which emails have accounts.
</Callout>

## Why these defaults

- **Argon2id** with OWASP 2024 parameters — memory-hard, GPU-resistant.
- **`verify` is a router** — it reads the PHC prefix, so bcrypt/scrypt/PBKDF2
  hashes from a legacy system verify unchanged, then `needsRehash` upgrades them.
- **Sessions are sealed cookies** — tamper-evident, with idle + absolute TTLs
  and server-side revocation, so logout is immediate.
